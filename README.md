# 👞 Tapkofon

Минималистичный веб-клиент Telegram для кнопочных телефонов и медленного интернета.
Обычный HTML, формы и cookies, без JavaScript. Работает на Telethon и FastAPI.
[Идея microclient](https://github.com/xadjilut/microclient).

## Возможности

- Чаты, сообщения, ответы, редактирование и удаление.
- Вход по номеру или QR, облачный пароль (2FA), выход из аккаунта.
- Загрузка вложений, кеш, сжатие изображений и аватаров.
- Конвертация аудио в MP3 и распознавание речи через Google.
- Текстовые обозначения эмодзи, локальные ссылки на Telegram-чаты.
- Пароль доступа к веб-клиенту.
- Текстовый режим по умолчанию, отдельное открытие фотографий и аватаров.
- Страницы по 5/10/20 элементов, непрочитанные и избранные чаты.
- Отдельная форма сообщения, быстрые ответы и сохранение текстового черновика.
- Единый лёгкий стиль и режим без оформления для простых браузеров.

### История и отметка прочитанного

«Старые сообщения» и «Новые сообщения» используют ID граничного сообщения
(`before` / `after` в URL), а не номер страницы. Новые сообщения и удаления
перед границей не сдвигают следующую выборку. «К последним» и «Обновить»
открывают свежую страницу. Параметр `page` для истории чата больше не используется;
нумерация страниц списка чатов остаётся прежней.

Автоматическая отметка прочитанного выполняется только на свежей странице,
после получения сообщений и успешного формирования HTML, до ID самого нового
показанного сообщения включительно. Telegram считает прочитанными и все более
ранние сообщения; это не отдельная отметка каждого видимого сообщения.
Переходы по истории, пустая выборка и ошибка получения/формирования страницы
не отправляют отметку. Сообщения, пришедшие после выборки, остаются непрочитанными.
Сервер не может подтвердить доставку HTML на телефон: обрыв соединения после
формирования страницы всё ещё возможен.

## Быстрый старт

Нужны [uv](https://docs.astral.sh/uv/getting-started/installation/) и FFmpeg в `PATH`.
Python 3.14 uv установит автоматически. Поддерживается Python 3.12 и новее.

FFmpeg: Linux — `sudo apt install ffmpeg`, Windows — `winget install Gyan.FFmpeg`,
macOS — `brew install ffmpeg`.

```console
git clone https://github.com/D4n13l3k00/tapkofon.git
cd tapkofon
uv sync --locked
uv run tapkofon
```

Адрес: <http://127.0.0.1:8888>. При первом запуске создаётся `session/config.toml`.
Остановите сервер, укажите собственные `api_id` и `api_hash`
из [my.telegram.org/apps](https://my.telegram.org/apps) и запустите его снова.
Войдите через страницу «Вход в Telegram»: сначала номер, затем код, при необходимости 2FA.
Альтернативный вход из терминала: `uv run tapkofon login` (при выключенном сервере).

По умолчанию сервер слушает только localhost. Для доступа с телефона:

```console
uv run tapkofon serve --host 0.0.0.0 --port 8888
```

Включите пароль через «Общие настройки и пароль» или CLI перед доступом извне; для интернета используйте HTTPS и
`cookie_secure = true`. Не запускайте несколько workers: приложение хранит одну
Telegram-сессию, ожидающий код входа и состояние доступа в одном процессе.
`/docs` — описание маршрутов, `/health` — проверка готовности HTTP-сервера
(она не проверяет подключение или авторизацию Telegram).

## Конфигурация и данные

По умолчанию все данные находятся в `session/` относительно папки запуска:
`config.toml`, `session.session`, `tapkofon.sqlite3` и `cache/`. Для постоянного пути задайте
`TAPKOFON_DATA_DIR`. Настройки читаются при запуске; после изменения перезапустите сервер.

В `config.toml` остаются серверные параметры. Они применяются после перезапуска.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `api_id`, `api_hash` | `0`, `""` | Ваше приложение Telegram API; не доступны из веба и не переносятся в базу |
| `cookie_secure` | `false` | Cookie только по HTTPS; включите при публичном HTTPS-размещении |
| `session_ttl_hours` | `24` | Максимальный срок веб-сессии (1–720 часов) |
| `pic_max_size`, `pic_avatar_max_size` | `256` | Резервные размеры; в вебе применяются профили телефонов |
| `msg_replace_regex`, `msg_regex_to` | см. `config.py` | Серверные правила замены ссылок |

В SQLite находятся общие настройки, доступные на `/admin`:

| Настройка | По умолчанию | Варианты |
| --- | --- | --- |
| Пароль доступа | Выключен | Включить, сменить, отключить |
| Качество изображений | 80 | 1–100 |
| Формат аватаров | JPEG | JPEG, PNG, WebP |
| Язык распознавания | ru-RU | Код языка Google Speech |
| Разрешить распознавание через Google | Включено | Да / нет |
| Локальные ссылки t.me | Включены | Да / нет |

Общие настройки применяются со следующего запроса без перезапуска.
`TAPKOFON_API_ID` и `TAPKOFON_API_HASH` переопределяют серверные credentials.
Старые `passwd`, параметры изображений/распознавания и `msg_regex_tme` при первом
запуске переносятся из TOML в SQLite и удаляются из файла. Пароль записывается
только как Argon2id-хеш. `access_cookie` больше не используется.
Старый `TAPKOFON_PASSWD` принимается только при первом заполнении общей записи;
после этого источником пароля служит база. Удалите устаревшую переменную из окружения.
Файлы сессии, конфигурации и базы исключены из Git и Docker build context.

## Пароль и защита

Для первоначальной установки откройте <http://127.0.0.1:8888/admin> на сервере.
Пока пароль выключен, управление общими настройками разрешено только с локального
адреса и через localhost/127.0.0.1/::1. Для Docker или удалённого сервера:

```console
uv run tapkofon password set
docker compose exec tapkofon tapkofon password set
```

CLI запрашивает пароль скрыто, не принимает его в аргументах.
Новый пароль: 15–256 символов, разрешены пробелы и Unicode. Существующий короткий
пароль при миграции сохраняется; ограничение применяется при новой установке/смене.
Смена или отключение пароля из веба требует текущего пароля. Для отключения также
нужно подтвердить открытый доступ. После смены все старые веб-сессии отзываются;
текущий браузер получает новую сессию. Забытый пароль сбрасывается через CLI.

Веб-сессии имеют случайные 256-битные токены; в базе хранятся только SHA-256-отпечатки,
привязка к браузеру и срок действия. Cookies: HttpOnly, SameSite=Lax и Secure при
`cookie_secure=true`. «Заблокировать» отзывает сессию и на сервере, и в браузере;
Telegram-сессия при этом остаётся активной. Выход из Telegram — отдельная операция.

POST-формы содержат скрытый CSRF-токен, привязанный к браузеру и версии защиты.
Он не требует JavaScript: достаточно обычных HTML-форм и cookies.
Origin/Referer дополнительно проверяются; страницы запрещено встраивать во фреймы.
После перезапуска или смены пароля старые формы нужно обновить.
Ошибочный пароль ограничен пятью попытками за пять минут с одного IP (счётчик в памяти).

Это общий доступ к одному Telegram-аккаунту, без отдельных пользователей и ролей.
Все, кто знают общий пароль, имеют доступ к аккаунту и общим настройкам. При отключённом
пароле клиент открыт всем, кто может подключиться. Для интернета нужен HTTPS:
хеширование пароля в SQLite не защищает пароль и cookie при передаче по HTTP.
Сама база, черновики и Telethon-сессия не зашифрованы: доступ к папке данных должен
оставаться закрытым. При reverse proxy настройте доверенные forwarded headers для
правильного определения HTTPS и адреса клиента; не доверяйте заголовкам от любых IP.

Конвертация аудио требует FFmpeg. Распознавание отправляет звук в Google и требует
интернета. Обычные сообщения, изображения и скачивание исходных файлов работают без FFmpeg.

## Вход по QR

В вебе откройте «Войти по QR-коду», создайте код и отсканируйте его из уже
авторизованного Telegram: Настройки → Устройства → Подключить устройство.
После сканирования нажмите «Я отсканировал — проверить»; JavaScript не нужен.
Если Telegram запросит облачный пароль, появится отдельная форма 2FA.
Истёкший код можно пересоздать. Изображение и состояние доступны только браузеру,
начавшему вход. Ожидание Telethon запускается до показа QR; фоновая задача очищается
при переключении на номер, выходе, смене пароля и остановке сервера.

В терминале (при остановленном веб-сервере с той же Telegram-сессией):

```console
uv run tapkofon login --qr
```

Код отображается контрастными блоками, обновляется после истечения срока,
облачный пароль запрашивается скрыто. Терминал должен быть достаточно широким.
Ссылка `tg://login` и токен QR не выводятся в HTML/логи и не записываются в SQLite.
Сам QR — временный секрет входа; его изображение не сохраняется в файловый кеш.
[Протокол QR-входа Telegram](https://core.telegram.org/api/qr-login).

## CLI и логи

CLI использует Typer и Rich. Без команды запускается сервер на localhost:8888.

```console
uv run tapkofon --help
uv run tapkofon serve --host 127.0.0.1 --port 8888
uv run tapkofon serve --reload
uv run tapkofon login
uv run tapkofon login --qr
uv run tapkofon db migrate
uv run tapkofon db history
uv run tapkofon password set
uv run tapkofon --data-dir ./session --log-level debug serve
uv run tapkofon --no-color --version
```

Логи отображают время UTC, уровень и сообщение через RichHandler.
Из access-логов удаляются параметры URL; traceback не показывает локальные
переменные или исходный текст исключения. Debug-логи ORM/Telethon выключены,
чтобы не записывать SQL-параметры и содержимое запросов. HTTP-формы, пароли и QR-ссылки
не журналируются. «db history» читает историю в режиме read-only и не применяет миграции.

## На кнопочном телефоне

В «Настройках» выбираются изображения, количество элементов на странице,
размер миниатюры (128/176/240 пикселей) и длина текста (300/600/1200 символов).
По умолчанию изображения не загружаются автоматически. Ссылка «Фото» открывает
миниатюру; оригинал скачивается отдельно. Аватары также открываются по запросу.

«Простое отображение без оформления» полностью отключает CSS. Страницы используют
обычные HTML-ссылки и формы: JavaScript, веб-шрифты и внешние стили не нужны.
Проверка в современном браузере на маленьком экране не заменяет проверку на телефоне.
Поддержка HTTPS, cookies и загрузки файлов зависит от его браузера.

Длинный текст сокращается в чате и раскрывается по ссылке «Полностью».
Фильтры «Все», «Непрочитанные» и «Избранные» доступны в списке чатов.
Чат добавляется в избранное кнопкой внизу переписки (до 32 чатов на браузер).

«Написать» открывает отдельную страницу с многострочным полем. Кнопка
«Прикрепить файл» сначала сохраняет текст и затем показывает выбор вложения;
обычная текстовая форма не требует multipart. «Сохранить черновик»
сохраняет текст; быстрый ответ вставляется в поле и не отправляется сам.
Перед отправкой текст тоже сохраняется, а после подтверждённой отправки удаляется
из черновиков. Если ответ Telegram потерялся, проверьте чат перед повтором.
Вложения в черновике не сохраняются: после ошибки файл нужно выбрать заново.
Обычное сообщение и ответ на конкретное сообщение имеют отдельные черновики.

Для аудио доступны обычный MP3, компактный MP3 (моно, 22,05 кГц, 32 кбит/с) и оригинал.
Распознанный текст кешируется отдельно для каждого языка и переживает перезапуск.
Настройки, избранное и черновики разделены по случайному идентификатору браузера
в cookie. После очистки cookies прежние настройки не подхватятся автоматически.

## SQLite и миграции

Tortoise ORM хранит в `session/tapkofon.sqlite3` настройки браузеров, избранное,
черновики, сведения о медиафайлах, результаты распознавания, общие настройки,
хеш пароля и веб-сессии. Сами медиа остаются
в `session/cache/`; Telegram-сессию обслуживает Telethon в своём файле.
SQLite использует WAL и ожидание блокировки 5 секунд.

При запуске применяются версионированные [встроенные миграции Tortoise](https://tortoise.github.io/migration.html)
из `tapkofon/migrations/`. Runtime не использует `generate_schemas` и не пересоздаёт
таблицы. Ручное применение миграций без запуска сервера:

```console
uv run tapkofon db migrate
uv run tapkofon db history
```

После изменения моделей в `db_models.py`:

```console
uv run tortoise makemigrations --name describe_change
uv run tapkofon db migrate
uv run pytest -q
```

Перед обновлением существующей установки остановите сервер и сохраните копию
всей папки `session/` (или `TAPKOFON_DATA_DIR`), включая обе SQLite-базы и кеш.
Очистка кеша удаляет файлы, их записи и результаты распознавания; настройки,
избранное и черновики сохраняются. JSON-файлы для состояния не используются.

## Docker

```console
docker compose up --build -d
```

Контейнер использует Python 3.14, FFmpeg и зависимости из `uv.lock`.
Данные сохраняются в локальной `session/`, порт привязан к `127.0.0.1:8888`.
Для внешнего доступа измените привязку порта и настройте пароль/HTTPS.
Процесс работает от UID 1000: на Linux перед первым запуском создайте папку
`session/` и предоставьте этому UID право записи (`mkdir -p session && sudo chown 1000:1000 session`).
При переносе существующей сессии также проверьте права её файлов.

## Разработка

```console
uv sync --locked
uv run tapkofon serve --reload
uv run ruff check .
uv run ruff format .
uv run pyright
uv run pytest -q
uv build
```

Обновление зависимостей: `uv lock --upgrade`, затем `uv sync --locked` и проверки.
Точные версии и хеши хранятся в `uv.lock`; `pyproject.toml` задаёт зависимости,
команду запуска и dev-группу. [Документация uv](https://docs.astral.sh/uv/concepts/projects/sync/).

Код разделён на `main.py` (создание приложения и lifespan), `config.py` (настройки),
`runtime.py` (Telegram-сессия и зависимости маршрутов), `routers/` (маршруты),
`media.py` (кеш/конвертация), `database.py`/`db_models.py` (SQLite), `migrations/`,
`preferences.py`, `app_settings.py`, `security.py`, `qr_auth.py`, `cli.py`,
`logging_config.py`, `models.py`, `utils.py` и `templates/`.
Импорт пакета не создаёт сессию или базу и не подключается к Telegram. Шаблоны и миграции включены в wheel.

Тесты используют подменённый Telegram-клиент; тест аудио вызывает настоящий FFmpeg,
но подменяет внешний запрос распознавания. Они не подтверждают реальный вход в Telegram.
CI проверяет Python 3.12–3.14 на Linux/Windows, сборку пакета и запуск Docker-контейнера.

## Переход со старой версии

- Запускайте команды из корня репозитория: `uv run tapkofon` вместо `run.sh`.
- Существующие `session/config.toml` и `session/session.session` используются дальше.
  Сделайте резервную копию перед обновлением. Старое окружение `.env/` больше не нужно.
- Кеш теперь находится в `session/cache/`; старый `tapkofon/cache/` можно оставить,
  новые вложения будут скачаны заново.
- `toml`, `pydub`, Black/isort и requirements-файлы заменены стандартным
  `tomllib`, FFmpeg, Ruff и `pyproject.toml`/`uv.lock`.
- Okteto и shell-скрипты удалены. Пароли передаются POST-формами;
  удаление сообщения, очистка кеша и выход требуют POST с токеном формы.
- Терминальная авторизация перенесена с `/auth_old` в `uv run tapkofon login`.
- Старые CLI-флаги `--login`, `--migrate`, `--set-password` заменены командами
  `login`, `db migrate`, `password set`; флаги запуска теперь относятся к `serve`.
